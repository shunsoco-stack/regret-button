# セキュリティとデータの扱い

## アプリの境界

後悔ボタンは端末内で動く小さな遊びです。決済、広告クリック、強制的な外部遷移、位置情報・連絡先・カメラへのアクセスは実装しません。音は Web Audio API で生成し、利用者が音を有効にした後の操作にだけ反応します。回数・前回の時刻・設定はブラウザーの localStorage に保存します。設定のリセットはこのアプリ自身の保存データだけを対象にします。

Vercel Analytics には操作の種類と固定された節目だけを渡し、端末内の履歴、任意の累計回数、前回の時刻、個人を識別する値はイベントに含めません。Analytics のページ閲覧・イベント処理にはネットワーク通信があり、アプリ全体が「一切通信しない」という意味ではありません。共有は利用者の操作でのみ実行され、送信先は利用者が選びます。

## オフラインキャッシュ

- Service Worker は本番ビルドかつ HTTPS（ローカル検証は localhost）でのみ登録します。登録や保存の失敗は通常の画面操作を妨げません。
- 初回オンライン表示時、ホームの HTML とそこに含まれる Next.js の静的アセット、アイコン、manifest を保存します。登録前に読み込まれた静的アセットも補完します。
- 同じオリジンの GET だけが対象です。ホームのナビゲーションはネットワーク優先、ハッシュ付きの `/_next/static/` はキャッシュ優先、固定名のアイコンと manifest はネットワーク優先です。
- 外部サイト、任意の API、RSC リクエスト、`/_vercel/insights/`、POST はキャッシュしません。エラーレスポンス、リダイレクト、`Cache-Control: no-store` のレスポンスも保存しません。
- 更新時に削除するのは `regret-button-` で始まる古いキャッシュだけです。他のアプリのキャッシュは削除しません。Service Worker の処理を変えるときは `public/sw.js` のキャッシュバージョンも更新してください。
- オフライン利用には、オンラインで一度開き、キャッシュの準備が完了している必要があります。ブラウザーがストレージを消去した場合やプライベートモードの制限下では、再びオンライン接続が必要になることがあります。

通知、プッシュ配信、バックグラウンド同期、位置情報の処理はありません。

## Secret Scan

`npm run secret-scan` は依存パッケージを必要としない、このリポジトリ用の静的スキャナーです。ソース、`public/` のテキストファイル、設定、README、ドキュメント、lockfile を含む作業ツリーを検査します。公開前と CI で実行します。

検出対象は次のとおりです。

- 秘密鍵の PEM ヘッダー、秘密鍵・キーストア形式のファイル名。
- GitHub、AWS、Google、Slack、Stripe の live key、OpenAI 形式、Vercel 形式の既知のトークンパターン。
- パスワードを含む一般的なデータベース接続 URL。
- secret / token / password / api_key 等の名前への長い認証情報らしい値の代入。明示的な `your_` / `example_` / `replace_` / `placeholder` / `changeme` で始まる例示値は、この汎用ルールだけで除外します。既知トークンのルールにはこの除外を適用しません。
- `.env` と `.env.*` のうち、名前が `.example` で終わらないファイル。内容が空でも失敗します。`.env.example` 自体も内容のスキャン対象です。
- 読めないファイル、検査対象内のシンボリックリンク。検査できなかったものを成功として扱いません。

除外するディレクトリは `.git`、`.next`、`.vercel`、`.tools`、`.cache`、`.npm-cache`、`.pnpm-store`、`node_modules`、`coverage`、`test-results`、`playwright-report` です。NUL バイトを含むバイナリファイルは内容の検査をせず、その件数を出力します。秘密鍵ファイル名の判定はバイナリにも適用します。

検出時は終了コード 1 を返し、ファイル名・行番号・ルール名のみを出力します。秘密値や該当行はログへ出しません。

### 限界と漏えい時の対応

2026-08-27の公開前には、公式配布物のSHA-256を確認したGitleaks 8.30.1でも作業ツリーを検査し、検出0件を確認しました。公開リポジトリではGitHub Secret ScanningとSecret Scanning Push Protectionを有効化済みです。Gitleaksのローカルツール・検査レポートは公開物に含めていません。

これはパターンによる予防検査であり、秘密情報が存在しないことを証明するものではありません。未知の形式、分割・難読化された値、画像や圧縮ファイルの内部、Git の過去履歴、除外した生成物、Vercel 等のサービス側環境変数は検査しません。誤検知・見逃しの両方があり得ます。公開する差分を人間が確認し、利用可能な場合は GitHub の secret scanning / push protection も併用してください。CI ファイルの追加だけでは、それらの GitHub 設定は有効になりません。

実際の認証情報を誤って公開した場合は、ファイルを消すだけでは不十分です。提供元で直ちに失効・再発行し、履歴、ビルド成果物、ログ、アクセス記録を確認してください。本アプリの動作に API キーや秘密の環境変数は不要です。

## CI の方針

GitHub Actions は main への push、pull request、手動実行で `npm ci`、Secret Scan、lint、typecheck、tests、production build、`npm audit --omit=dev --audit-level=high` を実行します。どれかが失敗したらジョブは失敗します。依存パッケージ監査は実行時点の npm advisory に依存し、開発用依存だけの問題はこの最後の監査ゲートの対象外です。

ジョブの権限は `contents: read` のみで、checkout の認証情報を残さず、公式 Actions を完全なコミット SHA に固定しています。[checkout v7.0.1](https://github.com/actions/checkout/releases/tag/v7.0.1) と [setup-node v7.0.0](https://github.com/actions/setup-node/releases/tag/v7.0.0) の公式リリースを確認して選定しています。外部アクションや lockfile の更新時にも変更内容を確認してください。

この workflow は検証を行いますが、GitHub のブランチ保護や Vercel のデプロイを自動的にブロックする設定までは行いません。公開前にローカルでも検証を完了し、継続運用ではこのジョブを必須チェックにする運用を推奨します。
